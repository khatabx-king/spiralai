## How SpiralAI Works

SpiralAI deliberately separates AI reasoning from scientific calculation and verification.

1. Muse Spark Open-1026 proposes a candidate design.
2. The deterministic Python physics engine calculates performance.
3. The independent verifier checks the result and model limits.
4. Verified feedback is returned to Muse.
5. Muse proposes a revised candidate.
6. The process repeats until a justified stopping state is reached.

The AI cannot change the physics equations or verification rules simply to make a candidate pass.

## Independent Verification

SpiralAI does not trust a numerical result simply because an AI generated it.

The verifier checks that:

- numerical performance came from the verified physics engine
- required evidence fields are present
- design parameters remain inside the supported screening range
- the requested target was actually achieved
- theoretical results are not represented as experimental results
- unsupported numerical claims are rejected
- higher-fidelity validation is requested when the screening model is insufficient

For example, a high-strain candidate outside the current conservative analytical screening boundary returns:

MORE_VALIDATION_REQUIRED

rather than being automatically accepted.

A fabricated AI-generated performance value that did not come from the physics engine returns:

INVALID_RESULT

This implements a core SpiralAI principle:

Muse designs. Physics calculates. The verifier decides.

## Scientific Scope and Limitations

Every current SpiralAI result is classified as:

THEORETICAL_SIMULATION

Current experimental validation:

NO

Current results are not:

- experimental measurements
- fabricated-device performance
- demonstrated cycle-life results
- demonstrated fatigue resistance
- proof of manufacturability
- proof that graphene mechanical storage can replace lithium-ion batteries

Real devices introduce additional effects including defects, fatigue, anchors, actuators, packaging, conversion losses, fabrication tolerances, control electronics, and mechanical coupling.

The current validation pathway is:

Analytical physics
-> numerical screening
-> AI-guided design
-> higher-fidelity FEA / molecular dynamics
-> fabrication
-> mechanical cycling
-> experimental validation

SpiralAI currently operates in the analytical, numerical-screening, and AI-guided-design stages.

## Run SpiralAI

Requirements:

- Python 3.9 or newer
- OpenAI-compatible Python SDK
- Baseten API key with access to the hackathon Muse Spark Open model

Install:

python -m pip install openai pytest

Set BASETEN_API_KEY as an environment variable.

Never place an API key directly in the source code or commit it to GitHub.

Run the iterative design agent:

python -m agent.iterative_agent

Run all automated tests:

python -m pytest -v

## Current Verification States

SpiralAI uses explicit stopping states:

- TARGET_REACHED
- TARGET_NOT_REACHED
- PHYSICAL_CONSTRAINT_VIOLATION
- MORE_VALIDATION_REQUIRED
- INVALID_RESULT
- INVALID_MODEL_OUTPUT
- NO_IMPROVEMENT
- MAX_ITERATIONS_REACHED

An unsuccessful design is still a valid scientific result.

SpiralAI does not force a positive conclusion.
